# wq_b_gemm — Indexer.wq_b Q low-rank expansion

Auto-mode A3 **cube** kernel that produces the per-head query of the
[Indexer](../README.md):
`q[B*S, N_HEADS*HEAD_DIM] = qr[B*S, Q_LORA_RANK] @ Wq_b[N_HEADS*HEAD_DIM, Q_LORA_RANK]^T`.

This is the `wq_b` projection inside `Indexer.forward`
([model.py:412](../../../../../../../deepseek/model.py)). The output is
then reshaped to `[B, S, N_HEADS, HEAD_DIM]` for the einsum in
`index_score`.

## Reference (CUDA / TileLang)

There is no dedicated TileLang kernel for `wq_b`; it dispatches through
the generic `linear()` in
[kernel.py](../../../../../../../deepseek/kernel.py) — same path as
`z_gemm` (see `HCA/Compressor/z_gemm/README.md`).

For the prototype, defaults to **BF16 inputs, FP32 accumulator** — matches
the `z_gemm` numerical contract.

## I/O

| Name | Shape | dtype | Source line |
|------|-------|-------|-------------|
| `qr`   | `(M = B*S, K = Q_LORA_RANK)`            | BF16 | model.py:411 (`qr = self.wq_a(x)`) |
| `Wq_b` | `(N = N_HEADS*HEAD_DIM, K = Q_LORA_RANK)` | BF16 | model.py:407 |
| `q`    | `(M, N)`                                 | FP32 | model.py:412 (then reshape) |

## Memory-budget-first plan

Per [CLAUDE.md §Memory-budget-first kernel planning](../../../../../../../CLAUDE.md):

```text
Memory budgets:
- L1 custom budget:    BF16 A panel + BF16 B panel + slack (target ≤ 256 KB)
- L0A custom budget:   one BF16 A fractal-tile [kTileM, kTileK]   (cube)
- L0B custom budget:   one BF16 B fractal-tile [kTileN, kTileK]   (cube)
- L0C custom budget:   one FP32 C fractal-tile [kTileM, kTileN]   (cube accumulator)
- UB custom budget:    one FP32 C tile staged for write-back

Live tiles by memory level:
- L1:  Atile (BF16, M×K_inner), Btile (BF16, N×K_inner)
- L0A: ATile (BF16, kTileM × kTileK fractal)
- L0B: BTile (BF16, kTileN × kTileK fractal)
- L0C: CTile (FP32, kTileM × kTileN fractal accumulator)
- UB:  CTile_fp32 staged for GM write

Smallest hardware operation:
- cube operation shape: 16×16×16 fractal MMA (BF16 × BF16 → FP32)
- vector operation shape: N/A

Loop tiling plan:
- tile-and-loop dimensions: M tiled by kTileM=64, N tiled by kTileN=128,
  K reduced by kTileK=64 (K-inner loop)
- inferred tile sizes: kTileM=64, kTileN=128, kTileK=64  (Assumption,
  pending profiler feedback; Q_LORA_RANK is small relative to DIM so K
  may even fit in one panel for tiny shapes)
- compile-time unroll/peel strategy: none for prototype
- tail handling only where needed: M tail when (B*S) % kTileM != 0;
  same reload pattern as MoE/router_matmul

Test-shape plan:
- tiny debug shape:        B=1, S=64,  QLR=128, N_HEADS=8,  HEAD_DIM=64
- medium tiling shape:     B=1, S=128, QLR=256, N_HEADS=16, HEAD_DIM=64
- model-inspired realistic: B=1, S=128, QLR=1024, N_HEADS=64, HEAD_DIM=128
- tail shape:              B=1, S=137, QLR=128, N_HEADS=8,  HEAD_DIM=64
```

## Auto-mode constraints

- A3 only; cube path: `--cce-aicore-arch=dav-c220-cube`.
- Single AICORE. No `block_idx` work split.
- No `TASSIGN`, `TPipe`, `TPUSH`/`TPOP`, no raw `set_flag`/`wait_flag`,
  no `Tile::data()` pointer casts.
- Wq_b reload every M-tile iteration — mirror MoE/router_matmul bMatTile pattern.
- Reason in 16×16 fractals in L0A/L0B/L0C.

## Build & run

bash run.sh -r npu -v Ascend910B1

## Comparison policy

- Tolerance-based: relative ≤ `1e-2`, absolute ≤ `1e-3` on FP32 output
  (BF16 GEMM with FP32 accumulator).
