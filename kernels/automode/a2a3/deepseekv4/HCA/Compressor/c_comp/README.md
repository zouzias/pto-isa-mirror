# c_comp — weighted-sum reduction across the ratio axis

Auto-mode A3 **vector** kernel that produces the compressed KV of the
[Compressor](../README.md):

```python
# model.py:343 — last step before norm/rope
kv_comp = (kv * softmax_score).sum(dim=2)
```

It consumes the outputs of [z_gemm](../z_gemm/) (after unflatten /
overlap_transform) and [biased_softmax](../biased_softmax/), and feeds
[rms_norm](../rms_norm/) and [rope](../rope/).

## Reference (CUDA / TileLang)

No dedicated TileLang kernel for this op; the python is a pointwise mul
followed by a sum-reduction along axis 2:

```python
out[b, sb, n] = sum_r( kv[b, sb, r, n] * softmax_score[b, sb, r, n] )
```

For `overlap=1` the python downstream then splits `kv_comp[..., :2d]` into
a `(..., 2, d)` view per `overlap_transform`. This split is **not**
performed by this leaf — see **Assumption** below.

## I/O

| Name | Shape | dtype | Source line |
|------|-------|-------|-------------|
| `kv`            | `(B, SB, R, N)` | FP32 | model.py:343 (post-unflatten/overlap) |
| `softmax_score` | `(B, SB, R, N)` | FP32 | model.py:343 (biased_softmax output) |
| `kv_comp`       | `(B, SB, N)`    | FP32 | model.py:343 (`.sum(dim=2)`) |

`R = ratio_eff = (2 * ratio if overlap else ratio)`,
`N = COFF * HEAD_DIM`. Shapes match [biased_softmax](../biased_softmax/).

## Memory-budget-first plan

Per [CLAUDE.md §Memory-budget-first kernel planning](../../../../../../../CLAUDE.md):

```text
Memory budgets:
- L1 custom budget:    not used (vector path; data flows GM → UB directly)
- L0A custom budget:   N/A
- L0B custom budget:   N/A
- L0C custom budget:   N/A
- UB custom budget:    one [R, N] FP32 kv tile + one [R, N] FP32 score tile
                       + one [1, N] FP32 accumulator → target ≤ 192 KB

Live tiles by memory level:
- UB:  KvTile (FP32, R × N), ScoreTile (FP32, R × N),
       ProdTile (FP32, R × N, reuses one of the above),
       AccTile (FP32, 1 × N)

Smallest hardware operation:
- cube operation shape: N/A
- vector operation shape: 256-byte lane (FP32 → 64 lanes) per VEC issue
  (Assumption — same baseline as add_tile_array)

Loop tiling plan:
- tile-and-loop dimensions: outer loop over (b, sb); inner reduction
  along R (axis 2). Each (b, sb) reads (R*N) FP32 twice and writes N FP32.
- inferred tile sizes: one (b, sb) per iteration; working set
  2 * R * N * 4 bytes ≈ 64 KB for realistic shape (fits UB)
- compile-time unroll/peel strategy: none for prototype
- tail handling only where needed: SB divides cleanly; R/N are
  pre-shaped by upstream kernels.

Test-shape plan:
- tiny debug shape:        B=1, SB=4,  R=8, N=64    → out (1, 4, 64)
- medium tiling shape:     B=1, SB=32, R=8, N=256   → out (1, 32, 256)
- model-inspired realistic: B=1, SB=64, R=8, N=1024 → out (1, 64, 1024)
- tail shape:              N/A (axes divide cleanly)
```

## Auto-mode constraints

- A3 only; vector path: `--cce-aicore-arch=dav-c220-vec` (see [CMakeLists.txt](CMakeLists.txt)).
- Single AICORE. No `block_idx` work split.
- No `TASSIGN`, `TPipe`, `TPUSH`/`TPOP`, no raw `set_flag`/`wait_flag`.
- Reduction along axis 2 uses sanctioned `TReduce*`; see
  [docs_for_ai/auto_mode_bad_patterns.md](../../../../../../../docs_for_ai/auto_mode_bad_patterns.md).

## Comparison policy

- Tolerance-based: relative ≤ `1e-3`, absolute ≤ `1e-4` on FP32 output.
  Pure FP32 mul + sum across ≤ 8 lanes — error is negligible.

## Status

- `Known`: shape contract / op definition matches the python forward
  (model.py:343). Inputs come from upstream `biased_softmax` and the
  unflattened `z_gemm` output.
- `Assumption`: this leaf produces `kv_comp` of shape `(B, SB, N)` where
  `N = COFF*HEAD_DIM`. For `overlap=1` the python downstream splits this
  into `(B, SB, 2, HEAD_DIM)` via `overlap_transform`; that split is
  **deferred** (a future leaf or a wiring pass).
- `Unknown` whether this builds — kernel body is a pseudocode skeleton, not
  a real implementation. **No claim of compile / run success** until the
  user runs `run.sh` on the compiler server and reports the output.
