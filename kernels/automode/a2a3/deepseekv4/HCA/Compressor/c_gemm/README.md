# c_gemm — Compressor.wgate linear projection

Auto-mode A3 **cube** kernel that produces the gating score of the
[Compressor](../README.md):
`score[b, s, coff*d] = X[b, s, dim] @ Wgate[coff*d, dim]^T`.

This is the parallel partner of [z_gemm](../z_gemm/) inside
`Compressor.forward` ([model.py:325](../../../../../../../deepseek/model.py)).
Its output feeds [biased_softmax](../biased_softmax/) (which adds the APE
bias and applies `softmax(dim=2)`).

## Reference (CUDA / TileLang)

There is no dedicated TileLang kernel for `wgate`; it goes through the
generic `linear` dispatch in
[kernel.py](../../../../../../../deepseek/kernel.py) which picks one of
`fp8_gemm`, `fp4_gemm`, or `F.linear` based on weight dtype (model.py:114-119).
In the DeepSeek-V4-Pro checkpoint, `wgate` is FP32 but quantized to BF16/FP8
on-load (model.py:296-299).

For this prototype, defaults to **BF16 inputs, FP32 accumulator** — same
numerical contract as `Compressor` (which casts `x = x.float()` at the
function entry, model.py:323).

## I/O

| Name | Shape | dtype | Source line |
|------|-------|-------|-------------|
| `X` | `(M = B*S, K = DIM)` | BF16 | model.py:317 (`x` after `.float()` cast — `Assumption`: we re-cast to BF16 for cube path) |
| `Wgate` | `(N = COFF*HEAD_DIM, K = DIM)` | BF16 | model.py:299 |
| `score` | `(M, N)` | FP32 | model.py:325 |

`COFF = 2` when `compress_ratio == 4` (overlap branch), else `COFF = 1`.

## Memory-budget-first plan

Per [CLAUDE.md §Memory-budget-first kernel planning](../../../../../../../CLAUDE.md):

```text
Memory budgets:
- L1 custom budget:    BF16 A panel + BF16 B panel + a bit of slack (target ≤ 256 KB)
- L0A custom budget:   one BF16 A fractal-tile [kTileM, kTileK]   (cube)
- L0B custom budget:   one BF16 B fractal-tile [kTileN, kTileK]   (cube)
- L0C custom budget:   one FP32 C fractal-tile [kTileM, kTileN]   (cube accumulator)
- UB custom budget:    one FP32 C tile staged for write-back

Live tiles by memory level:
- L1:  Atile (BF16, M×K_inner), Btile (BF16, N×K_inner)
- L0A: ATile (BF16, kTileM × kTileK fractal)
- L0B: BTile (BF16, kTileN × kTileK fractal)
- L0C: CTile (FP32, kTileM × kTileN fractal accumulator)
- UB:  CTile_fp32 staged for GM write

Smallest hardware operation:
- cube operation shape: 16×16×16 fractal MMA (BF16 × BF16 → FP32)
- vector operation shape: N/A (no vector ops in this leaf)

Loop tiling plan:
- tile-and-loop dimensions: M tiled by kTileM=128, N tiled by kTileN=128,
  K reduced by kTileK=64 (K-inner loop)
- inferred tile sizes: kTileM=128, kTileN=128, kTileK=64  (Assumption,
  pending profiler feedback; same as z_gemm by symmetry)
- compile-time unroll/peel strategy: none for prototype (single AICORE,
  simple double-loop)
- tail handling only where needed: last M tile may shrink to remainder
  when (B*S) % kTileM != 0; B reload pattern mirrors moe_segmented_gemm_relu

Test-shape plan:
- tiny debug shape:        B=1, S=16,  DIM=64,  COFF*HEAD_DIM=64    (single-tile, fits in L1)
- medium tiling shape:     B=1, S=128, DIM=128, COFF*HEAD_DIM=256   (2x2 tile grid)
- model-inspired realistic: B=1, S=256, DIM=4096, COFF*HEAD_DIM=1024 (full ModelArgs)
- tail shape:              B=1, S=137 (forces M tail), DIM=128, COFF*HEAD_DIM=128
```

## Auto-mode constraints

- A3 only; cube path: `--cce-aicore-arch=dav-c220-cube` (see [CMakeLists.txt](CMakeLists.txt)).
- Single AICORE. No `block_idx` work split.
- No `TASSIGN`, `TPipe`, `TPUSH`/`TPOP`, no raw `set_flag`/`wait_flag`,
  no `Tile::data()` pointer casts.
- Wgate reload every M-tile iteration — same pattern as
  [MoE/router_matmul](../../../../MoE/router_matmul/) (bMatTile reload).
- Reason in 16×16 fractals in L0A/L0B/L0C; **do not** treat tiles as flat
  row-major matrices.

## Comparison policy

- Tolerance-based: relative ≤ `1e-2`, absolute ≤ `1e-3` on FP32 output
  (BF16 GEMM with FP32 accumulator — small ULP drift expected vs the FP32
  numpy reference).

## Status

- `Known`: shape contract / I/O layout matches the python forward
  (model.py:325). Same dimensions as z_gemm by construction.
- `Assumption`: BF16 inputs (checkpoint is FP32 → BF16 on-load,
  model.py:299).
- `Unknown` whether this builds — kernel body is a pseudocode skeleton, not
