# rope — apply_rotary_emb on the last ROPE_DIM dims

Auto-mode A3 **vector** kernel that rotates the trailing `rope_head_dim`
slice of the compressed KV in the [Compressor](../README.md):

```python
# model.py:368
apply_rotary_emb(kv[..., -rd:], freqs_cis)
```

`apply_rotary_emb` (model.py:233-245) views the last `rd` values as
`rd/2` complex pairs `(re, im)` and multiplies each by a complex unit
`freqs_cis[s, k] = cos(theta) + i*sin(theta)` precomputed by
`precompute_freqs_cis` (model.py:200-230).

Expressed as real arithmetic for kernel implementation:

```
for each (s, k) in (S/ratio, rd/2):
  re_in = x[..., 2*k    ]
  im_in = x[..., 2*k + 1]
  cs    = freqs_cos[s, k]   # real part of freqs_cis[s, k]
  sn    = freqs_sin[s, k]   # imag part of freqs_cis[s, k]
  x[..., 2*k    ] = re_in * cs - im_in * sn
  x[..., 2*k + 1] = re_in * sn + im_in * cs
```

## I/O

| Name | Shape | dtype | Source line |
|------|-------|-------|-------------|
| `kv_tail`  | `(B, SB, ROPE_DIM)` | FP32 | model.py:368 (slice `[..., -rd:]`) |
| `freqs_cos` | `(SB, ROPE_DIM/2)` | FP32 | model.py:229 (`freqs_cis.real`) |
| `freqs_sin` | `(SB, ROPE_DIM/2)` | FP32 | model.py:229 (`freqs_cis.imag`) |
| `rotated`   | `(B, SB, ROPE_DIM)` | FP32 | model.py:243 (output) |

`SB = S / compress_ratio`. The python in-place rewrites `kv` itself; this
prototype writes a separate output buffer to keep the test harness simple.

`Assumption`: the complex `freqs_cis` is split into two FP32 buffers
(`real`, `imag`) so the kernel doesn't need a complex dtype. Conversion
happens in `gen_data.py`.

## Auto-mode constraints

- A3 only; vector path: `--cce-aicore-arch=dav-c220-vec` (see [CMakeLists.txt](CMakeLists.txt)).
- Single AICORE. No `block_idx` work split.
- No `TASSIGN`, `TPipe`, `TPUSH`/`TPOP`, no raw `set_flag`/`wait_flag`.
- Complex multiplication is implemented as 4 FP32 muls + 2 FP32 adds per
  pair (real-domain rewrite). The trig values are precomputed; **no**
  `sin`/`cos` inside the kernel.

## Status

  (model.py:233-245) restricted to `x[..., -rd:]`.
- `Assumption`: `freqs_cis` is split into two FP32 buffers (`freqs_cos`,
  `freqs_sin`). The kernel does **not** consume a `complex64` dtype.
