# biased_softmax — APE-biased softmax over the ratio axis

Auto-mode A3 **vector** kernel that produces the gating softmax of the
[Compressor](../README.md):

```python
# model.py:339, 342  (prefill path, after unflatten)
score = score.unflatten(1, (-1, ratio)) + self.ape
# overlap=True: score = overlap_transform(score, -inf)
softmax_score = score.softmax(dim=2)   # this leaf
```

It runs **after** [c_gemm](../c_gemm/) and feeds [c_comp](../c_comp/).

## Reference (CUDA / TileLang)

There is no dedicated TileLang kernel for the Compressor softmax; the
python path uses `torch.softmax(dim=2)`. The numerical form for a
length-`R` softmax row is:

```
row_max = max_i(score[i] + ape[i])
row_exp = exp(score[i] + ape[i] - row_max)
row_sum = sum_i(row_exp[i])
softmax = row_exp / row_sum
```

`R = ratio` when `overlap=0`, `R = 2*ratio` when `overlap=1`. The overlap
case adds `-inf` padding via `overlap_transform` (model.py:308-315); see
**Assumption** below for how this prototype handles that.

## I/O

| Name | Shape | dtype | Source line |
|------|-------|-------|-------------|
| `score` | `(B, S/ratio, R, N)` | FP32 | model.py:325 (after c_gemm + unflatten) |
| `ape`   | `(R, N)`             | FP32 | model.py:295 (`self.ape` parameter) |
| `softmax_score` | `(B, S/ratio, R, N)` | FP32 | model.py:343 (softmax output) |

With `R = ratio_eff = (2 * ratio if overlap else ratio)` and
`N = COFF * HEAD_DIM` matching c_gemm output.

The `B, S, ratio, overlap` come from the family manifest aliases
`kCompB, kCompS, kCompRatio, kCompOverlap`.

## Memory-budget-first plan

Per [CLAUDE.md §Memory-budget-first kernel planning](../../../../../../../CLAUDE.md):

```text
Memory budgets:
- L1 custom budget:    not used (vector path; data flows GM → UB directly)
- L0A custom budget:   N/A (no cube)
- L0B custom budget:   N/A
- L0C custom budget:   N/A
- UB custom budget:    one [R, N] FP32 tile + 2 reduction scratchpads
                       (row_max [R, 1], row_sum [R, 1]) — target ≤ 192 KB

Live tiles by memory level:
- UB:  ScoreTile (FP32, R × N), ApeTile (FP32, R × N once, reused),
       row_max scratch (FP32, R × 1), row_sum scratch (FP32, R × 1)

Smallest hardware operation:
- cube operation shape: N/A
- vector operation shape: 256-byte lane (FP32 → 64 lanes) per VEC issue
  (Assumption — same baseline as add_tile_array)

Loop tiling plan:
- tile-and-loop dimensions: outer loop over (b, s_block) with
  s_block = ceildiv(S/ratio, kTileSBlock); inner softmax is per-row of
  R values across N.
- inferred tile sizes: process one (b, s_idx) at a time → working set
  (R * N) FP32 ≈ 8 * 1024 * 4 ≈ 32 KB for the realistic shape (fits UB).
- compile-time unroll/peel strategy: none for prototype
- tail handling only where needed: (S/ratio) may not be a multiple of the
  block; handled by valid-region in auto mode.

Test-shape plan:
- tiny debug shape:        B=1, S=16,  COFF*HEAD_DIM=64,  ratio=4, overlap=1 → (1, 4, 8, 64)
- medium tiling shape:     B=1, S=128, COFF*HEAD_DIM=256, ratio=4, overlap=1 → (1, 32, 8, 256)
- model-inspired realistic: B=1, S=256, COFF*HEAD_DIM=1024, ratio=4, overlap=1 → (1, 64, 8, 1024)
- tail shape:              N/A (R and N divide cleanly; tail handled by S/ratio)
```

## Auto-mode constraints

- A3 only; vector path: `--cce-aicore-arch=dav-c220-vec` (see [CMakeLists.txt](CMakeLists.txt)).
- Single AICORE. No `block_idx` work split.
- No `TASSIGN`, `TPipe`, `TPUSH`/`TPOP`, no raw `set_flag`/`wait_flag`.
- Softmax reduction is along axis 2 (the `R` axis). Auto-mode reductions
  must use the sanctioned `TReduce*` form — see
  [docs_for_ai/auto_mode_bad_patterns.md](../../../../../../../docs_for_ai/auto_mode_bad_patterns.md).
- `ape` is broadcast across the (B, S/ratio) prefix; load it once per
  inner pass.

## Comparison policy

- Tolerance-based: relative ≤ `1e-3`, absolute ≤ `1e-4` on FP32 output.
  Softmax is FP32 throughout — tolerance is tighter than the GEMM leaves.

## Status

- `Known`: shape contract / I/O layout matches the python forward
  (model.py:339-343). `ape` parameter shape from model.py:295.
- `Assumption`: this prototype **omits** the overlap `-inf` mask. The
  golden numpy uses plain `softmax(dim=2)` over the full `R = 2*ratio`
  axis without the `overlap_transform` padding. Adding the mask is
  deferred to a follow-up leaf or to the wiring stage.
- `Assumption`: `ape` is supplied as a precomputed `(R, N)` FP32 tensor,
  not generated inline from the model parameter.
- `Unknown` whether this builds — kernel body is a pseudocode skeleton, not
  a real implementation. **No claim of compile / run success** until the
  user runs `run.sh` on the compiler server and reports the output.
