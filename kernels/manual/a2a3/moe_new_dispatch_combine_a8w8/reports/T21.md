# T21 Worker/Cache Scheduling

## Scope

- Target: initquant large-token worker selection and route-pack metadata cache.
- Keep PTO-only A8W8/int8 path; no AscendC/Catlass fallback.
- Keep routine logs lean: verification uses stop17 final summaries only.

## Implementation

- Worker selection now uses shared `M3NDispatchTargetWorkerCount`, driven by `M`, `topK`, `K`, `globalExpertNum`,
  logical AIV count, and fused lane-slot capacity.
- The selector balances token-centric quant work, `M * topK` route-store fanout, and `globalExpertNum * workerCount`
  prefix merge cost. It is shape driven and does not branch on small/large case names or fixed `topK`.
- Route-pack scatter now caches per-worker expert base and local ordinal in UB when `globalExpertNum <= 1024`.
  This removes per-route GM cursor read/write from the hot loop. Larger expert counts keep the GM cursor fallback with
  the same output contract.
- The fused stop17 path and the direct shard helper both use the same UB expert cache helpers.
