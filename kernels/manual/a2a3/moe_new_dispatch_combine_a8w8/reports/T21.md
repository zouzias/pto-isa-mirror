# T21 Worker/Cache Scheduling

## Scope

- Target: initquant large-token worker selection and route-pack metadata cache.
- Keep PTO-only A8W8/int8 path; no AscendC/Catlass fallback.
- Keep routine logs lean: verification uses stop17 final summaries only.

## Implementation

- Worker selection now uses a shared selector driven by `M`, `topK`, `K`, `globalExpertNum`, logical AIV count, and
  fused lane-slot capacity.
- The selector balances token-centric quant work and route-store fanout:
  - token-side worker demand scales with `K` and `topK`;
  - route-side worker demand scales with `M * topK`;
  - prefix merge cost caps workers when `globalExpertNum` is large.
- Route-pack scatter now caches per-worker expert base and local ordinal in UB when `globalExpertNum <= 1024`.
  This removes per-route GM cursor read/write from the hot loop. Larger expert counts keep the existing GM cursor
  fallback with the same output contract.
- The fused stop17 path and the direct shard helper both use the same UB expert cache helpers.
