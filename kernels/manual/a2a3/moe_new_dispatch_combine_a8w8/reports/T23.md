# T23 Metadata GM Batching

## Scope

- Target: reduce initquant metadata GM traffic for more-token/topK/more-expert paths.
- Keep PTO-only A8W8/int8 route quant path.
- Do not add intermediate debug logs or stop-stage dumps.

## Implementation

- Route scatter now builds a `M2RoutePackedRowsCache` while writing `expandedRowIdx` and `packedRowToRouteIndex`.
  Token-centric quant consumes this cache directly, so the hot path no longer writes `expandedRowIdx` and immediately
  reloads it from GM for the same token.
- Full-load and single-worker route pack invalidate `packedRowToRouteIndex` by expert ranges:
  `blockPrefixPerExpert[expert] + blockTokenPerExpert[expert]`.
- Multi-worker route pack invalidates `packedRowToRouteIndex` by worker/expert ranges:
  `blockPrefixPerExpert[expert] + initQuantWorkerPrefixPerExpert[worker, expert]` with
  `initQuantWorkerTokenPerExpert[worker, expert]` rows.
- `expandedRowIdx` remains flushed by the worker token-shard route range. Capacity-clip sparse updates still use a final
  full route-range flush to avoid long-lived sparse debug metadata.
