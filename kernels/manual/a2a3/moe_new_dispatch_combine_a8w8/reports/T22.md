# T22 GMM Cache Boundary Report

## Status

Accepted.

## Scope

T22 is a design/boundary task. It does not change kernel code.

The original FFN L1/L0 tile, swizzle, preload async pipeline, `SynchronizeBlock()` drain and small-group cache hint are
GMM1/GMM2 Catlass-stage optimizations. They are not initquant/front-reorder completion criteria.

Initquant/front-reorder performance hardening remains scoped to:

- UB resident full-load path;
- multi-AIV count/prefix/stable scatter;
- AIV-only phase sync;
- token-centric PTO Vec quant;
- metadata GM batching;
- row/column tiled quant for large K.

## Design Updates

- Added a T22 boundary conclusion in `design.md`.

- Kept token/topK/K parameter families in the GMM handoff. `small` and `large` are anchor cases only.
