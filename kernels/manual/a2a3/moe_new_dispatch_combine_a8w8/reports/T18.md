# T18 Sync Optimization Attempt Report

## Scope

T18 只收敛 initquant 前重排内部 worker 协作同步；跨 rank count publish/wait、dispatch gather handoff 和 stop17
final visibility 仍保留 hard/mix 边界。

## Attempt

- 尝试新增 initquant 内部 AIV-only phase sync helper。
- 尝试把 AIV worker assignment、state clear、worker scratch clear、route count、merge/prefix、scatter+quant
  周围的内部 hard/mix barrier 改成 AIV-only。
- 尝试调整 AIC 侧 `M3NDispatchAicWaitForAivSubphases` 的等待次数，避免 AIC 等待 AIV-only phase。

## Result

- small stop17 出现卡住，无法完成验收。
- 失败实现已撤回；当前生产 kernel 不包含本轮 AIV-only 同步替换代码。
- T18 维持 `needs_fix`，不能作为 T19-T21 的已完成依赖。

## Finding

当前 mixed kernel 的 stop17 路径存在 AIC/AIV `SYNCALL<Mix>` 配对关系。盲目把 AIV 侧内部同步替换为
AIV-only 后，AIC 侧仍可能在 mixed barrier 中等待，或者 AIV 侧进入 mixed final sync 时 AIC 未进入同一轮
barrier，导致卡住。

## Next Step

改代码前先建立 stop17/non-stop 同步配对表：

| Side | Site | Current role | Audit question |
| --- | --- | --- | --- |
| AIC | `M3NDispatchAicWaitForAivSubphases` | 与 AIV 多个 dispatch/initquant 子阶段配对 | 哪些轮次是 initquant 内部等待，哪些轮次属于后置 dispatch/GMM 边界 |
| AIC | stop17 final sync | host 验收前 mixed 可见性收口 | AIV final sync 是否有同轮 AIC 参与 |
| AIV | worker assignment/state clear/count/prefix/scatter | initquant 内部 worker 协作 | 是否可改为 AIV-only，且不影响后续 mixed sync 轮次编号 |
| AIV | count publish/wait/gather/ready | 后置 dispatch/GMM 衔接 | 是否必须继续 hard/mix 或改成明确跨核 event |
| AIV/AIC | debug stop early return | 调试停止路径 | early return 前是否已经消费同等数量 mixed barrier |

只有配对表确认后，才能逐点替换同步；禁止批量把 AIV 侧 hard sync 改成 AIV-only。
