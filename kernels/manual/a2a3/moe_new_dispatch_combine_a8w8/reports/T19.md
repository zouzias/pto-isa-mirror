# T19 UB-Fits Fast Path Report

## Scope

T19 implements a parameterized PTO full-load/UB-fits fast path for initquant front reorder. The path is selected by
`R=M*topK`, `K`, `globalExpertNum`, and output capacity, not by case name or fixed anchor shapes.

The first production slice keeps the output contract shared with the general path:

- local route count and expert prefix;
- capacity-clipped `expandedRowIdx`;
- `packedRowToRouteIndex`;
- token-centric PTO Vec quant to `dispatchPayload/dispatchScale`;
- final stop17 summary only.

## Design Review

Original FFN enters full-load dynamic quant when `R`, `K`, dropless mode, and UB fit constraints allow sort/count/quant
to be fused. The PTO path does not copy the AscendC full-load class. It uses the existing stable bucket semantics:

```text
count -> prefix -> scatter metadata -> token-centric quant
```

For UB-fits shapes this is executed by the main AIV with `workerCount=1`, avoiding the three internal
count/prefix/scatter AIV phase barriers. The surrounding mixed syncs are preserved so AIC/AIV protocol pairing remains
unchanged.

## Implementation

- Added host/device `InitQuantFullLoadFits` checks with conservative thresholds:
  - `routeCount <= 128`
  - `K <= 1024`
  - `globalExpertNum <= 16`
  - `maxOutputSize`/local rows can hold all routes
- Added `pto_full_load` report path for final stop17 logs.
- In mixed AIV initquant, full-load shapes run:
  - `M2CountLocalRoutes`
  - `M2RoutePackQuantLocal`
  - no internal initquant phase syncs
- `M2RoutePackQuantLocal` uses `M2QuantizeTokenToPackedRows`, so `topK>2` keeps token-centric quant.

## Remaining Work

T19 does not claim final commercial parity. The full-load threshold is intentionally conservative. T20/T21/T23/T24
must continue with larger token counts, ping-pong row/col quant, worker/cache tuning, metadata batch writes, and large-K
tiling before claiming broader production performance.
