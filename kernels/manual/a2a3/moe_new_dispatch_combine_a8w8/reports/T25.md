# T25 GMM PTO 性能设计报告

## Status

Accepted.

T25 是设计和任务拆分任务，不改 kernel 代码。目标是把后续 GMM1/GMM2 的 PTO 化设计清楚，避免把
initquant stop17 pass 误判为整算子的商用性能完成。

## Evidence Reviewed

- 当前 `design.md`：确认 T25 依赖 T22，GMM 必须继承 `M/topK/K/currentM` 参数族。
- 原 FFN `dispatch_ffn_combine.h`：确认 `L1TileShape=128x256x512`、`L0TileShape=128x256x128`、
  `preloadStages=1`、`l1/l0 ping-pong`、`GemmIdentityBlockSwizzle<9,1>`。

  `kGmmBaseM=128,kGmmBaseN=256,kGmmBaseK=64,kGmmStepK=4`，也就是 L1-K=256、L0-K=64。

## Key Design Constraints

- 不拷贝 Catlass/Catcoc/AscendC GMM 代码，只参考并发和缓存设计。
- GMM tile 是 AIC 工作单元，expert group 是 ready 边界，两者不能混为“某核负责某 expert”。
- `currentM` 必须来自前重排/dispatch 后的真实 expert row，不能按 small/large anchor 估算。
- 发布下游 ready 前必须 drain preload 和 final store。
- 若 PTO 缺少 L2 cache hint、L1-K=512 或 strided async return primitive，只记录 primitive gap，不退回 Catlass。
