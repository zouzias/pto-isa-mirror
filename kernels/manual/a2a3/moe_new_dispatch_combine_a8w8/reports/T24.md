# T24 大 K 行/列 Tiling 验收

## 结论

T24 accepted。前重排 route quant 在大 K 下保持 PTO Vec 主路径，`K=1024/7168,topK=4` 均通过 stop17，
`route_quant_scalar_fallback_reason=none`。本轮改动只增加 route-pack metadata store fence，用于保证
`expandedRowIdx/packedRowToRouteIndex` 写完后再做 cache-line 可见性处理；没有新增 case-name、固定 M 或固定
topK 的特化逻辑。

## 代码改动

- `M2RoutePackStoreFence()`：在 route scatter/quant 完成后执行 `pipe_barrier(PIPE_ALL)` 和 `dsb(DSB_DDR)`。
- 覆盖 base kernel、full-load PTO Vec 路径、multi-worker shard 路径和 mixed-spike PTO Vec 路径。
- 未保留中间 debug 日志、sync trace 或 payload/scale 额外刷新逻辑。

## 非特化检查

T24 不能按 small/large anchor 或 `topK=2` 优化。交付门禁：

```bash
rg -n "caseName|case_name|M == 16|M == 4097|topK == 2|slot < 2|packedRows\\[2\\]" \
  kernels/manual/a2a3/moe_new_dispatch_combine_a8w8/kernel
rg -n "initQuantSyncTrace|SyncTrace|timeline raw|counter dump|InvalidateDispatchPayloadScale" \
  kernels/manual/a2a3/moe_new_dispatch_combine_a8w8/kernel
```

两项均应返回空。

本轮结果：两项均返回空；`git diff --check` 通过；`scripts/check_pto_native_boundaries.sh` 输出
`[PASS] PTO-native boundary check passed`。

## 性能边界

当前结论只覆盖前重排 initquant 的 PTO Vec row/column tiling 和 metadata 可见性，不把 GMM 的 L1/L0、
swizzle、preload 计入完成项。GMM 对标 FFN 商用优化仍由 T25/T26 承接。
