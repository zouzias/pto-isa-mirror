# 第一章：总体概览介绍

本章介绍 PTO-ISA 的整体架构、目标用户、开发优势以及多框架支持。

---

## 1.1 PTO-ISA 概览

**PTO (Portable Tile Operations)** 是昇腾 CANN 设计的虚拟指令集架构，专注于 Tile 级别的操作。它提供跨昇腾平台的高性能、可移植的 Tile 操作能力。

### 什么是 Tile 编程？

Tile 编程是一种将大型张量（Tensor）分解为固定大小数据块（Tile）的编程范式：

```
┌─────────────────────────────────────────┐
│             大型张量 (GM)                │
│         1024 × 1024 × float             │
└─────────────────────────────────────────┘
                    │
                    │ 分块
                    ▼
┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐
│ Tile │ │ Tile │ │ Tile │ │ Tile │  ...
│64×64 │ │64×64 │ │64×64 │ │64×64 │
└──────┘ └──────┘ └──────┘ └──────┘
```

### PTO-ISA 在软件栈中的位置

```
┌─────────────────────────────────────────────────────────────┐
│                    应用层（用户代码）                          │
│         TileLang / PyPTO / PyTorch / TensorFlow             │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                      PTO-ISA（本项目）                        │
│            跨平台 Tile 操作指令集 + 运行时                    │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                     昇腾 NPU 硬件                            │
│              Ascend 910B / 910C / 950 等                    │
└─────────────────────────────────────────────────────────────┘
```

### 核心指令分类

| 类别 | 指令 | 功能 |
|------|------|------|
| **数据移动** | TLOAD, TSTORE, TMOV | 在内存层次间移动 Tile |
| **计算** | TADD, TMUL, TMATMUL | Tile 级算术运算 |
| **填充** | TFILLPAD | 处理边界和对齐 |
| **规约** | TROWREDUCE, TCOLREDUCE | 行/列方向规约 |
| **同步** | Event, set_flag, wait_flag | 流水线同步 |

## 1.2 目标用户

PTO-ISA 面向以下开发者群体：

### 架构研究者

- 研究 NPU 内存层次和数据流
- 分析和优化 Tile 级调度策略
- 探索新型 Tile 操作语义

- 将 PTO 能力集成到深度学习框架
- 开发跨平台兼容层
- 构建自动调优系统

## 1.3 PTO-ISA 开发融合算子的优势

### 优势一：细粒度内存控制

传统高层 API 隐藏了内存细节，而 PTO-ISA 让开发者显式控制：

```cpp
// 显式指定 Tile 在片上内存的位置
TASSIGN(tileA, 0x00000);  // UB 偏移 0
TASSIGN(tileB, 0x10000);  // UB 偏移 64KB

// 显式控制数据搬运路径
TLOAD(tileA, gmTensorA);   // GM → UB
TMOV(leftTile, matTile);   // L1 → L0A
```

**优势：**
- 消除不必要的数据拷贝
- 优化数据重用模式
- 精确控制缓冲区分配

### 优势二：显式流水线同步

PTO-ISA 的 Event 机制让流水线并行变得透明可控：

```cpp
Event<Op::TLOAD, Op::TADD> loadEvent;
Event<Op::TADD, Op::TSTORE_VEC> storeEvent;

// 异步加载
loadEvent = TLOAD(tile, src);

// 等待加载完成后计算
storeEvent = TADD(dst, tileA, tileB, loadEvent);

// 等待计算完成后存储
TSTORE(output, dst, storeEvent);
```

**优势：**
- 最大化硬件流水线利用率
- 避免不必要的同步屏障
- 支持复杂的生产者-消费者模式

### 优势三：跨平台可移植性

同一套 PTO 代码可在不同昇腾芯片上运行：

| 特性 | A2A3 (910B/C) | A5 (950) |
|------|---------------|----------|
| UB 大小 | 192KB | 256KB |
| L0C 大小 | 128KB | 256KB |
| 代码兼容 | ✅ | ✅ |

PTO-ISA 抽象了硬件差异，提供统一的编程接口。

### 优势四：融合算子优化

将多个操作融合在一个内核中，避免中间结果写回全局内存：

```
传统方式（多次 GM 访问）：
  GM → Softmax → GM → Scale → GM → MatMul → GM

融合方式（单次加载/存储）：
  GM → [Softmax → Scale → MatMul] → GM
        └─── 全部在片上完成 ───┘
```

**性能提升来源：**
- 减少全局内存带宽压力
- 降低内核启动开销
- 更好的数据局部性

## 1.4 多框架支持

PTO-ISA 支持多种上层框架，用户可根据需求选择：

```
┌─────────────────────────────────────────────────────────────────┐
│                        用户选择                                  │
│                                                                 │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────────────────┐ │
│  │  TileLang   │  │   PyPTO     │  │   PyTorch/TensorFlow    │ │
│  │ (Tile DSL)  │  │ (Python IR) │  │   (框架集成)             │ │
│  └──────┬──────┘  └──────┬──────┘  └───────────┬─────────────┘ │
│         │                │                     │                │
│         └────────────────┼─────────────────────┘                │
│                          │                                      │
│                          ▼                                      │
│              ┌───────────────────────┐                          │
│              │       PTO-ISA         │                          │
│              │  (统一指令集后端)      │                          │
│              └───────────────────────┘                          │
└─────────────────────────────────────────────────────────────────┘
```

### TileLang

**特点：** Python DSL，类似 Triton 的 Tile 编程风格

```python
import tilelang as tl

@tl.jit
def add_kernel(M, N):
    @T.prim_func
    def main(X: T.Tensor([M, N], T.float16),
             Y: T.Tensor([M, N], T.float16),
             Z: T.Tensor([M, N], T.float16)):
        with T.Kernel(M, threads=128) as (bx,):
            x = T.alloc_fragment([N], T.float16)
            y = T.alloc_fragment([N], T.float16)
            z = T.alloc_fragment([N], T.float16)
            
            T.copy(X[bx, :], x)
            T.copy(Y[bx, :], y)
            for i in T.Parallel(N):
                z[i] = x[i] + y[i]
            T.copy(z, Z[bx, :])
    return main
```

**适用场景：**
- 快速原型开发
- GPU 开发者迁移
- 研究和实验

### PyPTO

**特点：** Python 级 Tile IR，直接映射到 PTO 指令

```python
import pypto as pl

@pl.function(type=pl.FunctionType.InCore)
def tadd_kernel(
    a: pl.Tensor[[M, N], pl.FP32],
    b: pl.Tensor[[M, N], pl.FP32],
    output: pl.Out[pl.Tensor[[M, N], pl.FP32]],
):
    # 加载 Tile
    tile_a = pl.tile.load(a, [0, 0], [64, 64], target_memory=pl.MemorySpace.Vec)
    tile_b = pl.tile.load(b, [0, 0], [64, 64], target_memory=pl.MemorySpace.Vec)
    
    # 计算
    tile_c = pl.tile.add(tile_a, tile_b)
    
    # 存储
    pl.tile.store(tile_c, [0, 0], output)
```

**适用场景：**
- 编译器开发者
- 需要精确控制 IR 转换
- 构建自定义后端

### PyTorch 集成

**特点：** 通过自定义算子机制集成

```python
import torch
import torch_npu

# 方式 1：使用预编译的 PTO 算子
from pto_ops import pto_add
z = pto_add(x, y)

# 方式 2：通过 torch.compile 后端
@torch.compile(backend="ascend")
def my_function(x, y):
    return x + y
```

**适用场景：**
- 现有 PyTorch 模型加速
- 无需修改大量代码
- 生产环境部署

### 框架选择指南

| 需求 | 推荐框架 | 理由 |
|------|----------|------|
| 快速开发算子 | TileLang | 语法简洁，调试友好 |
| 精确控制底层 | PyPTO | 直接映射 PTO IR |
| 模型部署 | PyTorch 集成 | 与现有工作流兼容 |
| 研究新算子 | TileLang + PyPTO | 原型 + 优化组合 |

## 1.5 NPU 硬件架构概览

理解 PTO-ISA 需要了解底层硬件架构：

### AICore 结构

```
┌─────────────────────────────────────────────────────────────┐
│                         AICore                               │
│                                                              │
│  ┌─────────────────────────────────────────────────────┐    │
│  │                  L1 缓冲区 (512KB)                   │    │
│  │               Mat Tile（矩阵暂存）                    │    │
│  └─────────────────────────────────────────────────────┘    │
│                           │                                  │
│        ┌──────────────────┼──────────────────┐              │
│        ▼                  ▼                  ▼              │
│  ┌──────────┐      ┌──────────┐       ┌───────────┐        │
│  │   L0A    │      │   L0B    │       │    L0C    │        │
│  │  (Left)  │      │ (Right)  │       │   (Acc)   │        │
│  │   64KB   │      │   64KB   │       │  128KB    │        │
│  └──────────┘      └──────────┘       └───────────┘        │
│        │                │                   ▲              │
│        └────────────────┴───────────────────┘              │
│                         │                                   │
│                    ┌────┴────┐                              │
│                    │  Cube   │  （矩阵乘法单元）             │
│                    └────┬────┘                              │
│                         │                                   │
│  ┌─────────────────────────────────────────────────────┐   │
│  │              UB - 统一缓冲区 (192KB)                  │   │
│  │               Vec Tile（向量运算）                    │   │
│  │                      ┌────────┐                      │   │
│  │                      │ Vector │                      │   │
│  │                      │  Unit  │                      │   │
│  │                      └────────┘                      │   │
│  └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

### 内存层次

| 层级 | 名称 | 大小 (A2A3) | 延迟 | 用途 |
|------|------|-------------|------|------|
| 0 | 全局内存 (GM) | GB 级 | 高 | 模型参数、激活值 |
| 1 | L1 缓冲区 | 512KB | 中 | 矩阵 Tile 暂存 |
| 2 | UB | 192KB | 低 | 向量运算数据 |
| 3 | L0A/L0B | 64KB × 2 | 极低 | Cube 输入 |
| 4 | L0C/Acc | 128KB | 极低 | Cube 输出累加 |

### 数据流路径

```
全局内存 (GM)
     │
     │ TLOAD
     ▼
┌─────────┐
│   L1    │ ───── TMOV ───┬──▶ L0A (Left)
└─────────┘               │
     │                    └──▶ L0B (Right)
     │ TLOAD                        │
     ▼                              │ TMATMUL
┌─────────┐                         ▼
│   UB    │ ◀─────────────────── L0C (Acc)
└─────────┘                     
     │
     │ TSTORE
     ▼
全局内存 (GM)
```
