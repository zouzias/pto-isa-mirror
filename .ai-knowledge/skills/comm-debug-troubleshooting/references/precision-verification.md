# 通信精度验证

## 通信引入的精度问题

通信本身不应引入精度误差（数据搬运是精确的），但以下场景会产生精度差异：

### 归约顺序差异

浮点归约不满足结合律：`(a + b) + c ≠ a + (b + c)`

```
确定性归约：固定顺序 → 结果确定
非确定性归约：顺序可变 → 结果有微小浮动（但都在数学上正确）
```

**控制确定性**：
- A2 平台：设置 `HCCL_DETERMINISTIC=true`
- 950 平台：默认确定性

### 量化通信精度损失

量化通信（INT8/FP8）会引入量化误差：

```
原始数据 → 量化 → 通信 → 反量化 → 有损结果

精度损失 ≈ quantization_error × communication_count
```

## 验证方法

### 方法 1：与单卡结果对比

```
单卡结果 = MatMul(x1, x2)  (无通信)
多卡结果 = MatmulAllReduce(x1_chunk, x2)  (有通信)

比较：abs(单卡结果 - 多卡结果) < tolerance
```

### 方法 2：与 HCCL 非融合版本对比

```
非融合 = MatMul(x1, x2) + HcclAllReduce(result)
融合   = aclnnMatmulAllReduce(x1, x2)

比较：abs(非融合 - 融合) < tolerance
```

### 方法 3：自洽性检查

```
1 卡 AllReduce = 原始数据（通信无效果）
2 卡 AllReduce = 2 × 原始数据（每卡数据相同时）
```

## 精度指标

| 场景 | 典型 rtol | 典型 atol |
|------|----------|----------|
| FP16 无量化 | 1e-3 | 1e-3 |
| BF16 无量化 | 1e-2 | 1e-2 |
| INT8 量化通信 | 1e-2 | 1e-1 |
| FP8 量化通信 | 1e-2 | 1e-1 |

## 精度调试技巧

1. **逐步验证**：先验证纯通信正确，再验证融合正确
2. **小 shape 验证**：用小 shape 手算 golden 对比
3. **单卡 baseline**：先确保单卡计算正确
4. **量化分离**：先验证无量化版本，再加量化
5. **确定性模式**：开启确定性后对比多次运行结果是否一致
